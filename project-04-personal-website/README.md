# 项目 04：Agent 协同搭建与个性化装饰个人静态网站

## 1. 项目定位与目标
本项目利用 MkDocs 框架搭建个人静态网站。学生将在 AI Agent 的辅助下深入理解 MkDocs 技术栈，掌握高阶 Markdown 语法（包含图片、音频、视频等多媒体元素的嵌入），使用自定义 CSS 调整个性化网页背景与主色调，并实现本地机器上的预览与工程打包。

## 开始前：网站源文件与浏览器页面不是同一个东西

请先阅读[通用入门指南](../needtobeintroduced.md)。MkDocs 会读取配置和 Markdown 源文件，生成浏览器能够显示的 HTML、CSS 与 JavaScript：**你编辑 `docs/` 中的内容 -> MkDocs 构建 -> 浏览器加载页面与资源**。

- **Markdown**描述标题、段落、列表、链接等内容结构；它不是网页最终的外观。
- **HTML**表示页面结构，**CSS**决定颜色、间距和布局，**JavaScript**负责需要运行逻辑的交互。本项目主要修改 Markdown 与少量 CSS。
- **静态网站**是提前生成的一组文件，不需要服务器现场计算页面；`mkdocs serve` 只是提供本地预览并监听改动。
- `127.0.0.1` 表示你自己的计算机。只有同一台电脑能访问，不等于网站已经发布到互联网。
- 图片、音频等资源通过路径被页面引用。文件存在但路径或大小写不一致，浏览器仍可能加载失败。
- `site/` 是构建产物，通常应修改 `docs/` 与 `mkdocs.yml` 后重新构建，而不是直接编辑生成结果。

先只改 `docs/index.md` 的一个标题，观察预览页面是否自动变化；再加入一张体积较小、无隐私信息的本地图片。可以问 AI：“请沿着 `docs/index.md` 到浏览器页面解释这次变化经过了哪些文件；如果图片不显示，请给我一个逐项检查路径的办法。”把浏览器中的实际现象、终端报错和文件路径反馈给 AI，而不是只说“没用”。

## 2. 分阶段实施指南

### 推荐实施路线

按“先预览原站点 -> 改一页内容 -> 加一个资源 -> 改一项样式 -> 构建静态站点”的顺序推进。每一步刷新页面确认后再继续；不要让 Agent 一次重写 `mkdocs.yml`、全部 Markdown 和 CSS。

首次运行：

```powershell
python -m mkdocs serve
```

终端出现本地地址后再打开 `http://127.0.0.1:8000`。基线应至少有“首页、关于我、项目展示”三个导航入口。保持终端运行时页面才可预览；按 `Ctrl+C` 停止服务。

### 阶段 0：建站环境准备
在当前项目根目录下打开 Windows PowerShell，运行命令创建并激活虚拟环境：
```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install mkdocs-material
```
初始化站点并启动本地实时预览：
```powershell
mkdocs serve
```
在浏览器访问 `http://127.0.0.1:8000` 即可实时查看效果。

依次检查：终端是否位于含 `mkdocs.yml` 的项目根目录、Python 是否来自当前虚拟环境、端口是否被占用。若 `8000` 已占用，可让 MkDocs 换一个端口：

```powershell
python -m mkdocs serve -a 127.0.0.1:8001
```

把完整命令、终端最后十行和浏览器地址一起反馈给 AI，比只提供浏览器空白截图更容易定位问题。

---

### 阶段 1：站点配置与 Markdown 掌握（多媒体嵌入）
在 Agent 辅助下理解 `mkdocs.yml` 配置文件与 Markdown 语法规范：

1. **配置 `mkdocs.yml`**：设置站点名称、主题样式与导航目录。
2. **掌握高阶 Markdown 撰写**：
   * **基础语法**：标题层级、粗体、列表、代码块与表格。
   * **多媒体嵌入**：
     * 嵌入图片：`![个人头像](assets/avatar.png)`
     * 嵌入音频：`<audio controls src="assets/bgm.mp3"></audio>`
     * 嵌入视频：`<video controls width="100%" src="assets/demo.mp4"></video>`

先修改一个标题和一段文字，确认热更新生效；然后在 `docs/assets/` 中放入一个无隐私、文件名简单的小图片，并使用相对路径引用。图片不显示时依次检查：文件是否真实存在、路径相对于当前 `.md` 文件是否正确、扩展名和大小写是否一致、浏览器开发者工具是否显示 `404`。

编辑 `mkdocs.yml` 时一次只改一个配置项，并注意 YAML 缩进。每次保存后观察终端是否重新构建。可以问 AI：“请解释这段 `nav` 中每一级缩进的含义，并只检查语法；不要改写页面内容。”阶段证据是一张三页导航截图和一次有效的本地资源加载。

---

### 阶段 2：AI 协同 CSS 背景与个性化主题微调
在 Agent 的提示下编写 `docs/stylesheets/extra.css` 样式文件：
1. **背景定制**：为网站主体设置个性化渐变或纹理背景图像。
2. **视觉增强**：实现卡片悬浮过渡动画与圆角美化。
3. **引入配置**：在 `mkdocs.yml` 的 `extra_css` 配置中引入样式文件。

先在浏览器开发者工具中选择一个具体元素，确认其类名和当前样式，再让 AI 只生成针对该元素的一条规则。保存前写下预期，例如“正文背景变白但导航不变”；刷新后检查桌面宽度和窄窗口两种情况，确认文字仍可读、链接仍可见、多媒体没有超出页面。

在 `prompts_learnings.md` 中记录：原提示词、AI 建议、你实际采用的部分、修改文件、实际效果和一次后续追问。不要只粘贴生成代码；要说明为什么保留或拒绝某项样式。

---

### 阶段 3：静态打包与本地成果导出
运行命令 `mkdocs build`，项目将自动在本地生成包含完整 HTML/CSS/JS 静态文件的 `site/` 部署包。

```powershell
python -m mkdocs build --strict
```

`--strict` 会把部分警告作为失败处理，适合在交付前发现断链。构建成功后检查 `site/index.html`、样式文件和资源是否存在；不要直接修改 `site/`，应回到 `docs/` 或配置文件修改并重新构建。

局域网分享属于可选演示：只在可信网络和教师同意下临时监听局域网地址，并确认防火墙提示；演示结束立即停止服务。它不是互联网发布，也不要把含个人信息的页面用于共享测试。

## 3. 验收标准
- [ ] 本地预览包含三个可访问导航页面，内部链接和实际使用的本地资源均可加载。
- [ ] 用一项内容修改说明 Markdown、MkDocs 构建和浏览器页面之间的关系。
- [ ] CSS 修改在桌面和窄窗口下均可读，并保留一组修改前后对照。
- [ ] `python -m mkdocs build --strict` 通过，成果来自源文件重新构建而非直接修改 `site/`。
- [ ] `prompts_learnings.md` 记录提示词、采用/拒绝的建议、实际验证和后续追问。

## 4. 工程目录结构
```text
project-04-personal-website/
├── README.md             # 本说明文档
├── mkdocs.yml            # 站点主配置文件
├── docs/                 # 页面源文件目录
│   ├── index.md          # 首页 (包含富媒体与个人介绍)
│   ├── about.md          # 关于我
│   ├── projects.md       # 实训项目展示
│   ├── assets/           # 静态资源 (图片/音频/视频)
│   └── stylesheets/      # 样式文件 (extra.css)
├── site/                 # mkdocs build 生成的本地静态部署包
└── prompts_learnings.md  # Agent 协同 Prompt 记录
```
